启动一个新代理自主处理复杂的多步骤任务。

使用 Task 工具时，你必须指定 subagent_type 参数来选择合适的代理类型。

何时不使用 Task 工具：
- 如果要读取特定的文件路径，请使用 Read 或 Glob 工具代替 Task 工具，以更快找到匹配项
- 如果要搜索特定的类定义如 "class Foo"，请使用 Grep 工具代替 Task 工具，以更快找到匹配项
- 如果在特定文件或 2-3 个文件集中搜索代码，请使用 Read 工具代替 Task 工具，以更快找到匹配项
- 如果没有合适的代理可用于该任务，请直接使用其他工具

使用说明：
1. 尽可能同时启动多个代理以最大化性能；为此，在单条消息中多次使用工具调用
2. 将工作委派给代理后，不要重复做相同的工作。继续处理不重叠的任务，或等待结果。对于后台任务，结果准备好时你会自动收到通知。
3. 代理完成后，它会向你返回一条消息。代理返回的结果对用户不可见。要向用户显示结果，你应该向用户发送一条包含简洁结果摘要的文本消息。输出包含一个 task_id，你可以稍后重用以继续同一个子代理会话。
4. 除非你提供 task_id 恢复同一个子代理会话（该会话会继续之前的消息和工具输出），否则每次代理调用都从全新上下文开始。从头开始时，你的提示应包含高度详细的任务描述，让代理自主执行，并且你应准确指定代理在其最后且唯一一条消息中应返回什么信息。
5. 代理的输出通常应被信任
6. 明确告诉代理你期望它编写代码还是仅做研究（搜索、文件读取、网页获取等），因为它不知道用户的意图。如有可能，告诉它如何验证工作（例如，相关的测试命令）。
7. 如果代理描述提到应主动使用，那么你应尽力在没有用户先要求的情况下使用它。自行判断。
