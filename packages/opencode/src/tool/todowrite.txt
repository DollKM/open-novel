创建和维护当前编码会话的结构化任务列表。跟踪进度、组织多步骤工作、向用户展示状态。

## 何时使用
主动使用当：
- 任务需要 3+ 个不同的步骤或操作（不仅仅是单个概念步骤的 3 次工具调用）
- 工作非平凡且受益于规划
- 用户提供多个任务（编号或逗号分隔）或明确要求 todo 列表
- 新指令到达——将其捕获为待办项
- 你开始一个任务——在工作前标记为 `in_progress`（一次只能有一个）
- 你完成一个任务——标记为 `completed` 并添加工作中发现的任何后续事项

## 何时不使用
跳过当：
- 工作是一个简单的直接任务（或少于 3 个简单步骤）
- 请求纯粹是信息性或对话性的
- 跟踪没有组织价值

## 状态
- `pending` - 未开始
- `in_progress` - 正在积极工作（一次只能有一个）
- `completed` - 成功完成
- `cancelled` - 不再需要

## 规则
- 实时更新状态；不要批量完成
- 仅在所需工作实际完成后才标记为 `completed`，包括任何必要的验证。绝不能基于意图。
- 在工作未完成时，始终保持恰好一个 `in_progress`
- 如果受阻或部分完成，保持 `in_progress` 并添加一个描述阻塞器的后续待办项
- 逐字保留用户提供的命令（标志、参数、顺序）
- 事项应具体且可操作；将大工作分解为更小的步骤

## 示例

使用它：
- "添加深色模式开关并运行测试" -> 多步骤功能 + 显式验证
- "跨仓库将 getCwd 重命名为 getCurrentWorkingDirectory" -> grep 显示 8 个文件中有 15 处
- "实现注册、目录、购物车、结账" -> 多个复杂功能

跳过它：
- "如何在 Python 中打印 Hello World？" -> 信息性
- "给 calculateTotal 添加注释" -> 单次编辑
- "运行 npm install 并告诉我发生了什么" -> 一个命令

拿不准时，就用它。
