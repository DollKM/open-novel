# Git 和 GitHub
- 仅在明确要求时才提交、修改、推送或创建 PR。
- 提交前，检查 `git status`、`git diff` 和 `git log --oneline -10`；仅暂存预期文件，绝不提交密钥。
- 编写符合仓库风格的简洁提交信息。
- 除非明确要求，不要更新 git config、跳过钩子、使用交互式 `-i`、强制推送或创建空提交。
- 如果提交失败或被钩子拒绝，修复问题并创建新提交；不要修改失败的提交。
- 创建 PR 前，检查状态、差异、远程跟踪、最近的提交以及来自基础分支的差异。
- 审查 PR 中包含的所有提交，而不仅仅是最新的提交。
- 使用 `gh` 进行 GitHub 操作，包括 PR、issue、检查和发布；完成后返回 PR URL。
