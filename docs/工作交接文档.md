# 工作交接文档

## 原始需求

为 `POST /api/provider/proxy` 端点编写**全栈集成测试**，模拟客户端真实 HTTP 请求，验证从路由分派 → 中间件 → handler → Catalog 查询 → buildModel → LLMClient.stream → SSE 响应的完整链路。

该端点位于 `packages/server/src/handlers/provider.ts`，通过 `ProviderGroup` 注册在 `packages/server/src/api.ts` 的 `Api` 中，作为 `HttpApiApp.routes` 的一部分暴露。

## 当前阶段目标

搭建可运行的集成测试框架，使以下 5 个测试场景通过：

| # | 场景 | 期望 |
|---|------|------|
| 1 | 正向：发正常 payload，proxy 转发到 TestLLMServer，返回 SSE | 200 + `event: message` + 响应内容 |
| 2 | 未知 providerID | 404 + `ProviderNotFoundError` |
| 3 | 已知 provider + 未知 modelID | 503 + `ServiceUnavailableError` |
| 4 | model API type 为 `native`（不支持） | 503 + "does not use AI SDK routing" |
| 5 | 缺少 modelID/messages 的 payload | 503 + "Invalid proxy request body" |

```
testEffect 层栈:
  httpApiLayer           ← HttpApiApp.routes（完整路由树 + 全量服务）
  TestLLMServer.layer    ← fake upstream LLM（监听随机端口）

```

- Catalog 数据通过 `catalog.transform()` 动态注入，不走 ModelsDev/数据库
- API key 通过 `setEnvScoped("TEST_PROXY_KEY", "sk-test")` 从环境变量注入
- TestLLMServer 通过 `llm.url` 将 baseURL 注入到 model 的 `api.url`

### 关键发现

1. **`Catalog.Service` 不直接可用**：在 `HttpApiApp.routes` 架构中，Catalog 通过 `LocationMiddleware` → `LocationServiceMap.layer` 在每个请求的 per-location 层栈中提供，不在全局上下文。测试体不能直接 `yield* Catalog.Service`。

2. **`Catalog.layer` 的依赖树**：
   - `Catalog.layer` → Location, PluginV2, EventV2, Policy, Credential, Scope
   - `PluginV2.layer` → EventV2, Scope
   - `Policy.layer` → Location（**构建时立即 yield**，不能用 Layer.mergeAll 随机顺序）

3. **`LocationMiddleware` 问题**：测试请求到达时，`HttpApiApp.routes` 内置的 `LocationMiddleware` 会触发 `LocationServiceMap.lookup()`，构建完整的 per-location 层栈（含 20+ 服务：Catalog, PluginV2, Config, Reference, FileSystem, Pty, PluginBoot...）。这些服务在测试上下文中不存在，导致请求挂起 21s 后 fiber 被中断。

## 推荐下一步

### 选项 A（推荐）—— 用 no-op LocationMiddleware 绕过 per-location 构建

```ts
import { LocationMiddleware } from "../../../server/src/groups/location"
const noopLocation = Layer.succeed(
  LocationMiddleware,
  LocationMiddleware.of((effect) => effect),
)
// 在 testEffect 的 mergeAll 中加入
```

`LocationMiddleware` 的作用是解析请求中的 `x-opencode-directory` 头，提供 per-location 的 Catalog 实例。由于测试已通过 `catalogDeps` 提供了全局 Catalog，no-op middleware 不会影响 proxy handler 的正常工作。

### 选项 B —— 直接调用 handler，绕过 HTTP 路由

不经过 `HttpApiApp.routes`，直接构建 `HttpApiBuilder.group(Api, "server.provider", ...)` 的最小层栈。优点是无 LocationMiddleware 干扰；缺点是不测试路由和中间件层。

### 选项 C —— 提供完整的 LocationServiceMap 依赖

在测试层栈中补齐 `LocationServiceMap.lookup()` 所需的所有服务（Config, FileSystem, Pty, PluginBoot, SkillV2, Reference, RepositoryCache, Watcher 等 20+ 项）。优点是最大真实性；缺点是维护成本高，每次新增/修改 location 层依赖都需要同步修改测试。

### 建议

走**选项 A**，先让集成测试跑通。`LocationMiddleware` 的 per-location 逻辑属于另一个关注域，在 proxy 测试中 mock 掉是合理的权衡。

## 实际实现方案（此 session 完成）

### 问题：选项 A 不 work

`LocationMiddleware` 在 `server/src/handlers.ts` 中通过 `Layer.provide(locationLayer)` 被深度嵌入 `handlers` 层内部。`httpApiLayer`（通过 `HttpApiApp.routes` = `createRoutes()`）的 `serverRoutes` 已在内部 wiring 好生产环境的 `LocationMiddleware`，外部 `Layer.mergeAll` 无法覆盖。

### 实际方案：新建最小化 HttpApi

创建独立的测试路由栈，只包含 `ProviderGroup`，不经过生产 `handlers` 层：

1. 创建 `ProxyApi = HttpApi.make("test-proxy").add(ProviderGroup)`
2. 用 `HttpApiBuilder.group(ProxyApi, "server.provider", ...)` 注册 handler，直接调用 `handleProviderProxy`
3. 提供 noop `LocationMiddleware`（`Layer.succeed`）
4. 用 `HttpRouter.serve` 独立启动，配合 `NodeHttpServer.layerTest`

### 生产代码修改

`packages/server/src/handlers/provider.ts` 中提取了 `handleProviderProxy(request)` 函数，替换原来的内联 handler。

### 修复的 bug

1. **body 解析方式**：原来 `(request.source as Request).json()` 只兼容 Web API Request，测试环境 Node 下 `request.source` 是 `IncomingMessage`。改为 `request.text` + `JSON.parse`。
2. **SSE 断言**：实际返回 LLMClient.step 格式（`text-delta` 等），不是 `event: message`，测试断言已调整。

### 层栈关键点

`catalogDeps`、`LLMClient.layer`、`TestLLMServer.layer`、`pluginBootMock` **必须** `Layer.provideMerge` 到 `testHttpLayer` 内部，不能放在外层 `testEffect(Layer.mergeAll(...))`，否则 handler 运行时取不到 `Catalog.Service`。

### 最终层栈

```
testEffect 层栈（自包含）:
  testHttpLayer
    ├─ HttpRouter.serve(testApiLayer)
    │   ├─ HttpApiBuilder.layer(ProxyApi)
    │   │   └─ provideMerge(testProxyHandler)
    │   │       └─ handleRaw → handleProviderProxy(ctx.request)
    │   └─ provide(noopLocationMiddleware)
    ├─ NodeHttpServer.layerTest
    ├─ NodeServices.layer
    ├─ TestLLMServer.layer
    ├─ catalogDeps（Catalog + PluginV2 + Policy + EventV2 + Location + Credential）
    ├─ pluginBootMock（PluginBoot.wait → void）
    └─ LLMClient.layer + RequestExecutor.defaultLayer + WebSocketExecutor.layer
```
